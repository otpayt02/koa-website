# KOA Mobile Preview

Use the canonical runner and real React route. Do not substitute `public/koa`, a source-only review, or a stale local server.

## Trigger

Use this skill when a KOA change needs mobile browser proof, a `390×844` Design Studio comparison, an overflow check, or Motion-off evidence.

## Inputs

- Repository root, normally `C:\Users\olive\Projects\koa-website`.
- Locale and route, defaulting to `/en`.
- Named milestone or frame to prove.
- Evidence directory and filename prefix.
- Whether the existing runtime may be reused after its repository, route, and process identity are verified.

## Workflow

1. Inspect `git status`, the current runner contract, and the requested evidence boundary.
2. Start the canonical application with `scripts/run-koa.ps1`, or reuse only a runtime proven to serve this repository. Record its URL and stop command.
3. Open the real route in browser automation at exactly `390×844`.
4. Exercise the requested state and check `document.documentElement.scrollWidth <= document.documentElement.clientWidth`, film-chrome overlap, keyboard reachability, and runtime exceptions.
5. Toggle the application Motion control off. Verify complete semantic content, stable identity, no active canvas clutter, no glimmer, and a static partner layout.
6. Emit sanitized, named screenshots and a compact JSON result under the requested evidence directory. Include route, viewport, Motion state, milestone, overflow, exceptions, and redaction status.
7. Stop only the process owned by this run with the printed stop command. Never terminate an unidentified listener.

## Output

Return the exact URL, viewport, tested state, evidence paths, overflow result, Motion-off result, runtime exception list, start/stop ownership, and any limitation. A screenshot alone is not a passing result.

## Verification

Verify one ordinary mobile state and the Motion-off state. Confirm named evidence exists, horizontal overflow is zero, the runtime exception list is empty, and the captured route is the canonical React application.

## Approval boundary

This workflow may start and stop a local owned process and write sanitized local evidence. It may not deploy, publish, upload, change external accounts, approve translations or partner claims, capture private material, or delete historical artifacts without explicit approval.
